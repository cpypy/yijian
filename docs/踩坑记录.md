# 踩坑记录

从「跑通引擎」到「三平台出安装包」这一路踩到的问题。按「现象 → 根因 → 修法」记，方便以后回查，也方便别人少踩一遍。

分三类：**Windows 权限与环境**、**打包**、**CI**。最后是还没解决的问题。

---

## 一、Windows 权限与环境

### 1. `python -m venv` 直接失败

**现象**

```
Error: Command '...\python.exe -m ensurepip --upgrade --default-pip'
returned non-zero exit status 1
```

**根因**：受限环境下 `ensurepip` 跑不起来（目录 ACL + 临时目录写入被拦）。

**修法**：放弃 venv，改用 `pip install --target`，最后改成直接解压 wheel（见第 3 条）。

---

### 2. pip 安装时报 `Permission denied`

**现象**

```
ERROR: Could not install packages due to an OSError:
[Errno 13] Permission denied: '...\pip-unpack-xxx\fastapi-0.162.0-py3-none-any.whl.metadata'
```

**排查过程**

- 把 `TMP`/`TEMP` 指到工作区 → 仍然报错
- 手写 `O_TEMPORARY` 文件 → 成功，排除 delete-on-close
- 最终确认是 pip 的解包写入被沙箱拦截

**修法**：提权（`danger-full-access`）安装。但这引出下一个坑。

---

### 3. 提权装完，目录读不了

**现象**：`.deps/texlate` 的 `__init__.py` 读不出来，`import texlate` 得到的是空 namespace package（`__file__ is None`）。

**根因**：提权进程与沙箱进程的安全上下文不同，创建出来的目录 ACL 不匹配。

**修法**：不再用 pip 落地，改成「下载 wheel → 用 `zipfile` 解压」。

- 脚本：`tools/bootstrap_deps.py`
- 产物目录：`.runtime/`

这条路反而是最稳的：没有临时文件、没有安装器、纯文件写入。

---

### 4. `Path.mkdir(mode=0o700)` 把目录锁死

**现象**：texlate 建完 `data/texlate`，紧接着自己就读不了（`Permission denied`）。

**根因**：Windows 上 `mkdir(mode=0o700)` 会收紧目录 ACL 到创建者令牌，沙箱用户之后无法访问。

**修法**：运行时打补丁，把 `Path.mkdir` 的 `mode` 参数吞掉：

```python
if os.name == "nt":
    _orig = Path.mkdir
    def _mkdir(self, mode=0o777, parents=False, exist_ok=False):
        return _orig(self, parents=parents, exist_ok=exist_ok)
    Path.mkdir = _mkdir
```

落点：`sidecar/runner.py` 的 `_patch_texlate()`，以及开发态的 `tools/patch_runtime.py`。

---

### 5. tectonic 报 `os error 10106`

**现象**

```
error: this bundle isn't cached, and we couldn't get it from the internet.
caused by: tcp open error
caused by: 无法加载或初始化请求的服务提供程序。(os error 10106)
```

**根因**：texlate 的编译子进程用 env **白名单**过滤环境变量，把 `SYSTEMROOT` 过滤掉了。Windows 上缺它，Winsock 初始化失败，任何 socket 都建不起来。

**踩坑点**：`filtered_env` 是**按名字精确匹配**的，而 `os.environ` 里存的是大写 `SYSTEMROOT`，所以补 `SystemRoot` 无效，必须补 `SYSTEMROOT`。

**修法**：白名单加 `SYSTEMROOT`、`WINDIR`、`USERPROFILE`、`APPDATA`、`LOCALAPPDATA`、`COMSPEC`。

---

### 6. tectonic 缓存写进 `%LOCALAPPDATA%`

**现象**：`failed to create directory C:\Users\...\AppData\Local\TectonicProject\...`

**根因**：同样因为白名单没有 `TECTONIC_CACHE_DIR`，tectonic 回落到默认缓存位置。

**修法**：白名单放行 `TECTONIC_CACHE_DIR`，并显式指向项目内的 `data/tectonic-cache`。

---

### 7. bundle 下载走不了代理

**现象**：修完 10106 之后，报 `error sending request for url (...tar.index.gz)`。

**根因**：白名单连 `HTTPS_PROXY` 一起过滤了。

**修法**：放行 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY`（含小写形式）。

---

### 8. texlate 拒绝非空的工作目录

**现象**

```
--work-dir 已存在且非空，拒绝覆盖删除
```

**根因**：应用层先建了任务目录并写入日志，texlate 看到目录非空就罢工。

**修法**：任务目录和编译目录分开——日志写 `jobs/<id>/run.log`，texlate 的工作目录下沉到 `jobs/<id>/build/`。

---

## 二、打包

### 9. 单文件 exe 解压失败

**现象**

```
[PYI-4752:ERROR] Failed to extract Lerc.dll: failed to open target file!
```

**根因**：onefile 模式启动时要把 294 MB 解压到 `%TEMP%`，受限环境下写不进去。

**修法**：改 onedir（速度快、不解压），整个目录作为 Tauri 资源打包。

---

### 10. PyInstaller 在 Anaconda 环境里失控

**现象**：构建 20 多分钟不结束，日志显示在扫描 `torchvision`、`cv2` 的 DLL 搜索路径。

**根因**：Anaconda 的 site-packages 太大，PyInstaller 顺着 `PATH` 把整个环境犁了一遍。

**修法**：不在本机构建，交给 CI 的干净 Python 环境。构建时间从「不可控」变成 40 秒。

---

### 11. texlate 根本没被打进 sidecar

**现象**：sidecar 能启动，但转发给 `--texlate` 时报 `ModuleNotFoundError: No module named 'texlate'`。

**根因**：构建时 `PYTHONPATH` 只有 PyInstaller 自己，没有 `.runtime`，`collect_all("texlate")` 静默失败（异常被 `try/except` 吞了）。

**修法**：构建时 `PYTHONPATH=.build/pyi;.runtime`，并在构建后断言 `_internal/texlate` 存在。

**教训**：`collect_all` 包在 `try/except` 里时一定要打日志，否则「少了东西」和「没少东西」看起来一样。

---

## 三、CI（GitHub Actions）

### 12. `CI=true` 让 texlate 拒绝下载 tectonic

**现象**：三个平台都在 `Install tectonic` 这一步 1 秒内失败。

**根因**：texlate 检测到 `CI` 环境变量就默认关闭自动下载。

**修法（第一版）**：设置 `TEXLATE_NO_DOWNLOAD=0`、`CI=""` —— 在 Windows 上仍然不生效。

**修法（最终）**：彻底绕开它的安装器，直接下载官方二进制：

```bash
curl -fL -o data/texlate/tools/tectonic.pkg "$BASE/$ASSET"
python -c "用 zipfile/tarfile 解压"
```

---

### 13. unix 上「装了个寂寞」

**现象**：tectonic 这步在 macOS/Linux 上 1 秒「成功」，但 `data/texlate/tools/` 是空的，sidecar 里没有编译器。

**根因**：安装器在下载被禁时以 0 退出，只打印一行“缺失”。

**修法**：同第 12 条，改成显式下载 + `ls -la` 验证。

**教训**：CI 里「成功」不等于「做成了」，关键步骤后面要跟一句校验。

---

### 14. 创建 Release 权限不足

**现象**：macOS/Linux 构建全过，最后一步挂掉，注解写着：

```
Resource not accessible by integration - create-a-release
```

**根因**：workflow 没有声明 `permissions`，`GITHUB_TOKEN` 默认只读。

**修法**

```yaml
permissions:
  contents: write
```

---

### 15. AppImage 打包失败

**现象**：Linux 的 `Build installers` 跑了 5 分钟然后失败，没有有用的注解。

**推断**：AppImage 依赖 linuxdeploy，在 runner 上不稳定。（日志需要仓库管理员权限才能读，我这边拿不到，所以只能推断。）

**修法**：按平台指定 bundle 类型：

```yaml
windows -> nsis
macos   -> dmg
linux   -> deb
```

代价是 Linux 只出 `.deb`，没有 AppImage。

---

### 16. GitHub 自己挂了

**现象**：`git push` 报 `remote rejected ... Internal Server Error`，连续三次；同一时间状态页显示 `Minor Service Outage`。

**修法**：等几十秒重试。推送脚本里加了 6 次重试。

---

### 17. 匿名 API 限额

**现象**：轮询构建状态脚本突然报 `KeyError: workflow_runs`。

**根因**：GitHub 匿名 API 限额 60 次/小时，被我轮询用光了。

**修法**：降低轮询频率、解析前先判 `status_code`、用另一条出口（工具内置的抓取）绕过。

## 五、几条通用经验

1. **受限环境里，pip 是最脆的一环**。wheel 解压反而最稳。
2. **Windows 上「白名单 env」几乎必踩坑**：`SYSTEMROOT`、`TEMP`、代理变量，一个都不能少，而且大小写要按实际存的来。
3. **CI 的「成功」要加断言**。`ls -la` 比退出码诚实。
4. **构建和运行环境要分开**。Anaconda 里打包 = 给 PyInstaller 一座垃圾山。
5. **出错先看是不是环境**。这一路十几个问题里，只有一个是代码逻辑（工作目录非空），其余全是权限、编码、路径、网络。
