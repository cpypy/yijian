# 译见 · 桌面双语论文阅读器 — 设计方案 v1.1

> 一句话：把「发现一篇论文 → 收进自己的文库 → 一键变成中英对照、公式排版正确、可离线精读」做成一个 Windows 桌面应用，翻译用自己的 API Key，按量付费，不再被订阅制卡脖子。

---

## 0. 一页纸结论

| 项 | 决定 |
|---|---|
| 产品名 | **译见（Yijian）** |
| 形态 | Windows 桌面应用（可扩展 macOS），无浏览器、无手动起服务 |
| 核心链路 | arXiv/本地文件 → LaTeX 解析分段 → LLM 段落级翻译 → ctex 重编译 → 双语阅读 |
| 引擎策略 | **fork texlate 进仓库自持**（Apache-2.0），可自由修改；不重写解析与编译 |
| 发现 | 全站热榜（直接采用 alphaXiv Hot，客户端只做去重、打散、中文速览）；一键译入；手动刷新不设冷却 |
| 技术栈 | Python 3.12 + FastAPI（本地环回）+ React/Vite + pywebview(WebView2) |
| 首版周期 | 8 周（单人全职估算） |
| 安装包 | ≈ 150 MB（含 TeX 引擎与中文字体） |

三个判断，决定了整个方案：

1. **不要解析 PDF。** 幻觉翻译和 texlate 的质量来自「拿到 LaTeX 源码，只翻译段落文本」。PDF 重排是另一个难度量级的问题，v1 只在没有源码时降级处理。
2. **不要重写引擎。** texlate 已经把取源、分段、占位符保护、编译修复、对齐数据做完了，而且是 Apache-2.0。自己重写至少多花两个月，效果还更差。
3. **桌面版的价值不在「把网页包一层」**，而在**文库**和**发现**：论文是长期资产，需要分类、检索、进度、离线、系统集成。这是 texlate 的 Web 形态天然做不好的。

## 1. 和现有产品的差异

| | 幻觉翻译 | texlate（Web） | **译见（桌面）** |
|---|---|---|---|
| 计费 | 订阅制 | 自备 Key | 自备 Key + 本地缓存，重复阅读 0 成本 |
| 使用方式 | 网页上传 | 起服务 + 浏览器 | 双击打开，拖文件即用 |
| 论文来源 | 上传 | 手输 arXiv ID | **全站热榜一键入馆；检索与订阅后续补** |
| 资产管理 | 无 | 任务列表 | **文库：分类、标签、智能集合、全文搜索** |
| 离线 | 否 | 否 | 已译内容与 PDF 全离线 |
| 集成 | 无 | Zotero 插件 | 系统「打开方式」、剪贴板监听、托盘、Zotero/BibTeX |

一句话定位：**texlate 是「翻译工具」，译见是「论文工作台」。**

## 2. 名字

### 主推：译见（Yijian）

- **构词**：译（翻译）+ 见（看见），谐音「遇见」。
- **为什么贴产品**：发现页每天做的事就是「遇见」新论文；阅读页做的事是「译见」它的中文一面。一个词同时覆盖两个主场景。
- **英文/技术标识**：`Yijian`，可执行文件 `Yijian.exe`，应用 ID `app.yijian.desktop`，数据目录 `%APPDATA%\Yijian`。
- **Slogan**：`译见 · 遇见论文的中文一面`
- **风险**：与「意见」同音，口头介绍时需要补一句；上线前查一下商标与 `yijian.app` 域名归属。

### 备选

| 名字 | 含义 | 适合度 |
|---|---|---|
| **译栈** | 谐音「驿站」，论文在此歇脚、被翻译、被收藏 | 强调文库属性，技术感略重 |
| **墨读** | 谐音「默读」，墨水 + 阅读 | 强调阅读体验，弱化了翻译 |
| **纸间** | 纸页之间，谐音「指尖」 | 文艺，但检索辨识度低 |

选名原则：能同时容纳「译」和「读」，两个音节，能当 exe 名，输入法一次打得出。译见最均衡。

## 3. 用户与场景

**Persona A｜研究生（高频）**
每天刷 arXiv 新稿，看到相关就存，存完不看。痛点不是「找不到」，是「存了读不完」。
→ 订阅 + 一键译入 + 只读摘要/引言的「十分钟速读」模式。

**Persona B｜工程师（低频高价值）**
为落地某个方法去读论文，只关心公式、实验设置、结论。
→ 段落级对照、公式保真、术语表、笔记导出。

**Persona C｜跨方向研究者**
本方向以外的论文，英文术语不熟。
→ 术语高亮、引用卡片一键译入、AI 追问「这段在说什么」。

核心场景（按频率排序）：

1. 早上打开，看订阅推送的 3 篇新论文摘要 → 挑 1 篇译入。
2. 从 Zotero / 别人发来的 arXiv 链接 → 粘贴 → 自动入馆并排队翻译。
3. 精读：左原文右译文，公式、引用、图表编号都在原位。
4. 写综述：按分类/标签筛出 30 篇，批量导出 BibTeX 与摘要译文。

### 5.1 技术选型对照

| 方案 | 安装包 | UI 自由度 | 复用 Python 引擎 | 结论 |
|---|---|---|---|---|
| Electron + React | 220 MB+ | 高 | 需 sidecar + IPC | 多一个运行时，不选 |
| PySide6 (Qt) | 120 MB | 中 | 直接 import | 阅读器排版要重写，不选 |
| Tauri + Rust | 40 MB | 高 | 需 sidecar | Rust 维护成本高，不选 |
| **pywebview + React** | **150 MB** | **高** | **直接调用** | **选它** |

选 pywebview 的核心理由：后端本来就是 Python，引擎也是 Python，再引入第二个运行时（Node/Electron）纯粹是负担；而 WebView2 在 Win10/11 上随 Edge 预装，安装包不需要带浏览器内核。前端仍可用 React 写成现代界面，阅读器的排版能力（KaTeX、CSS 分栏、滚动同步）一点不少。

**代价**：pywebview 的多窗口/原生菜单能力弱。本产品单主窗 + 模态对话框足够，可接受。若后续需要更强壳能力，把前端换成 Electron 只改 Layer 0，EnginePort 以下不动。

### 5.2 进程模型

| 进程 | 职责 | 崩溃影响 |
|---|---|---|
| 主进程（Python） | pywebview 窗口、FastAPI、SQLite、调度 | 整体退出，重启恢复任务 |
| 引擎子进程 | texlate 管线、LLM 调用、编译 | 只挂当前任务，主进程标记失败可重试 |
| TeX 子进程 | tectonic / xelatex | 超时 120s 杀掉，走降级 |

引擎必须独立进程：LaTeX 编译会吃满 CPU 并可能死循环，Python 的 GIL 和异常都拦不住，隔离后可以「杀掉重来」。

### 5.3 本地通信安全

- 只监听 `127.0.0.1`，端口随机。
- 启动时生成 32 字节随机 token，通过 URL fragment 传给 WebView，前端所有请求带 `Authorization`。
- 校验 `Origin`，拒绝非本应用来源。
- API Key 存 Windows 凭据管理器（`keyring`），**不落 SQLite、不进日志**。

## 6. 引擎层：复用 texlate 的边界

texlate 的模块划分（`src/texlate/`）与本项目的对应关系：

| texlate 模块 | 作用 | 我们的用法 |
|---|---|---|
| `arxiv/` | 拉取源码、缓存 | 直接用 |
| `latex/segmenter` | LaTeX 结构切分、段落识别 | 直接用 |
| `chunk.py` | 分块与批处理 | 直接用 |
| `xlat/` | 翻译管线、占位符 | 直接用 |
| `validate/` | 占位符/长度/结构校验 | 直接用 |
| `repair/`、`compile/fixloop` | 编译错误自动修复 | 直接用 |
| `align.py`、`server/seqpos` | 段落与 PDF 位置对齐 | 直接用，产出 `dual.json` |
| `compile/` | ctex 注入、引擎调度 | 直接用 |
| `share.py` | 译稿共享包 | P1 |
| `server/worker` | 任务执行与事件 | 作为子进程 API 消费 |

**结论：几乎全用，我们只写壳；但壳要能改到引擎里面去。** texlate 目前是 `0.1.1`，`pyproject.toml` 里大量模块标注「另一会话在飞区」，上游迭代快、内部 API 不稳。所以不做「黑盒依赖 + 适配层」，而是 **fork 进仓库自持**（详见 §18）：

1. `git subtree` 把上游放进 `vendor/texlate/`，保留 upstream remote 以便同步。
2. 需要什么就改什么：优先级队列、按段重译、prompt 覆盖、人工修订回写 PDF——上游没有的能力直接加。
3. 改动登记在 `PATCHES.md`，每两周同步一次上游，30 篇回归集守住编译成功率。
4. 引擎仍跑在子进程里，崩溃可杀可重试；fork 只改变「能不能改」，不改变进程隔离。

### 6.1 EnginePort 接口

```python
class EnginePort(Protocol):
    def probe(self) -> EngineStatus: ...            # python/tectonic/字体/模型连通性
    def submit(self, src: SourceRef, opts: JobOpts) -> JobId: ...
    def stream(self, job: JobId) -> Iterator[Event]: ...   # SSE：stage/progress/segment_done
    def cancel(self, job: JobId) -> None: ...
    def result(self, job: JobId) -> Artifacts: ...  # zh_pdf/en_pdf/dual_json/src_zip/log
    def retranslate(self, doc: DocId, seg_ids: list[str]) -> JobId: ...
    def compile_pdf(self, doc: DocId) -> JobId: ...
```

适配器实现 A：调 `vendor/texlate` 起的本地引擎（默认，HTTP + SSE）。
适配器实现 B：进程内直接调用（fork 后可自建稳定入口，用于单测）。
**两套实现可切换**，引擎崩了能独立重启，不影响主进程。

### 6.2 任务状态机

```
queued → fetching → parsing → translating → validating → compiling → done
             ↘ fail(可重试)      ↘ partial(降级交付)          ↘ canceled
```

每条状态转换都写 `jobs` 表并推 SSE，前端据此驱动进度条、卡片徽章、失败重试按钮。**任何一步失败都不能让整篇论文不可读**——`translating` 完成即可进入阅读器，`compiling` 在后台继续，这是「边翻边读」的基础。

### 6.3 边翻边读

texlate 的 Web 是「提交 → 等 → 看结果」，桌面版改成流式：

1. 解析完成立刻拿到段落列表，阅读器先渲染**原文**和**骨架译文**。
2. 引擎每译完一批（默认 8 段），推 `segment_done` 事件，前端就地填充，带 200ms 淡入。
3. 用户滚动到未译段落时，前端把该段 id 插队到翻译队列头部（`priority` 参数）。
4. 编译在后台进行，完成后状态栏提示「zh.pdf 已就绪」，不阻塞阅读。

这个改动带来一个关键体验差：**3 分钟的任务，第 15 秒就能开始读**。

## 7. 翻译质量与成本

### 7.1 分段与占位符保护

原文：

```latex
The dominant sequence transduction models are based on complex recurrent or
convolutional neural networks \cite{sutskever2014} that include an encoder and
a decoder, with cost $O(n^2)$ per layer.
```

送给模型的文本（公式、引用、脚注全部替换为占位符）：

```
The dominant sequence transduction models are based on complex recurrent or
convolutional neural networks {{C1}} that include an encoder and a decoder,
with cost {{M1}} per layer.
```

翻译后回填：

```
主流的序列转换模型基于复杂的循环或卷积神经网络 {{C1}}，包含编码器与解码器，
每层开销为 {{M1}}。
```

规则：

- 占位符格式 `{{C1}}`（cite）、`{{R1}}`（ref）、`{{M1}}`（math）、`{{F1}}`（footnote）、`{{U1}}`（url）。
- **只送纯文本 + 占位符**，绝不把 LaTeX 命令交给模型改写。
- 中文标点统一全角，英文术语保留原文并在首次出现加括号注释（可配置）。

### 7.2 提示词结构

```
[system]
你是学术论文翻译器。把英文段落译成简体中文，遵守：
1. 保留 {{Cn}} {{Rn}} {{Mn}} 等占位符，数量与位置不变，不得翻译或增删；
2. 术语严格使用给定对照表；
3. 学术书面语，不用「我们」，被动语态可转主动；
4. 不添加解释、不扩写、不省略；
5. 只输出 JSON：{"id": "...", "zh": "..."}

[context]
论文标题 / 本章标题 / 前一段译文（仅作语气参考，不要复述）

[glossary]
attention → 注意力
query → 查询
...

[input]
{"id":"p_0031","text":"..."}
```

### 7.3 校验闭环

模型输出后逐项检查，任一项不过就带错误信息重试一次，再失败降级保留原文并标记 `failed`：

| 检查项 | 规则 | 不通过的处理 |
|---|---|---|
| JSON 结构 | 能解析且含 `id`/`zh` | 重试（强约束提示） |
| 占位符集合 | 与原段完全一致（多重集） | 重试，指出缺失/多余的编号 |
| 中文占比 | 汉字数 / 总字符 > 0.45 | 判为未翻译，重试 |
| 长度比 | 0.35 < len(zh)/len(en) < 2.4 | 判为截断/啰嗦，重试 |
| LaTeX 泄漏 | 不含 `\cite` `\ref` `\begin` 裸命令 | 重试 |
| 术语一致 | 术语表词条命中且译法正确 | 标记 warning，不重试 |
| 重复退化 | 与上一段译文相似度 < 0.9 | 重试（防复读机） |

**降级是有价值的**：一篇 200 段的论文里有 2 段失败，不应该让整篇不可用。失败段落用淡红底 + 「重译」按钮标出，用户可手动处理。

### 7.4 缓存

缓存键：

```
sha256( 规范化原文 + 目标语言 + 模型标识 + 提示词版本 + 术语表哈希 )
```

- 存 `translations` 表，**跨文档全局复用**。同一篇论文重开、换机器导入译稿包，都能命中。
- 术语表变更会让哈希变化，触发相关段落重译——这是刻意的，保证一致性。
- 前端状态栏显示实时命中率，让用户直观看到「省钱」。

### 7.5 成本预估

一篇 8000 词的论文 ≈ 11k 输入 token + 9k 输出 token。

| 模型档位 | 输入 | 输出 | 单篇成本 | 100 篇 |
|---|---|---|---|---|
| DeepSeek-V3 | ¥1/M | ¥2/M | ≈ ¥0.03 | ≈ ¥3 |
| Qwen-Plus | ¥0.8/M | ¥2/M | ≈ ¥0.03 | ≈ ¥3 |
| GPT-4o | ¥18/M | ¥72/M | ≈ ¥0.85 | ≈ ¥85 |
| Claude Sonnet | ¥21/M | ¥105/M | ≈ ¥1.2 | ≈ ¥120 |

结论：**用国产模型跑量，单篇三分钱**，比订阅制便宜两个数量级。设置页要内置这张价格表，实时算账；再给一个「单篇预算上限」，超了就暂停问用户。

### 7.6 术语一致性

- 全局术语表（用户维护）+ 领域预设包（NLP / CV / 生物 / 经济）。
- 首次翻译时，从标题与摘要抽 5–10 个候选术语，让用户一次性确认，之后全库生效。
- 阅读器里选中英文术语 → 「加入术语表」，后续所有论文都按新译法。

## 8. 文库与分类管理

这是桌面版的核心资产，设计目标：**三个月后回来，还能找到那篇论文。**

### 8.1 概念模型

| 概念 | 说明 | 约束 |
|---|---|---|
| 集合 Collection | 树形文件夹，一篇论文可属多个集合 | 多对多 |
| 标签 Tag | 扁平、可多选、可着色 | 多对多 |
| 智能集合 Smart | 保存的查询条件（分类+年份+状态+标签） | 动态求值 |
| 状态 Status | 未读 / 在读 / 已读 / 归档 | 单选 |
| 收藏 Star | 布尔 | 单选 |
| 进度 Progress | 阅读百分比，按滚动位置记录 | 0–100 |

### 8.2 自动归类（降低维护成本）

手工分类没人坚持。提供三条自动化：

1. **导入即归类**：按 arXiv 主分类映射到默认集合（cs.CL → 自然语言处理），可关。
2. **规则引擎**：`标题含 "survey" → 打 #综述`；`引用 > 500 → 打 #经典`。规则可编辑、可预览命中。
3. **相似推荐**：入库时用标题+摘要算相似度，提示「这篇和《Attention…》很像，加入同一集合？」（本地 BM25，无需 embedding 也可用）

### 8.3 去重

- 主键：`arxiv_id`（唯一索引）。
- 兜底：DOI 归一化；标题去标点小写后做 SimHash，汉明距离 ≤ 3 视为重复，导入时提示合并。
- 同一论文的「原文版/译文版/多个来源」合并为一条记录，多个附件挂在下面。

### 8.4 检索

SQLite FTS5，建两张虚拟表：`fts_title_abs`（英文）与 `fts_zh`（译文），查询时 UNION 并按 BM25 排序。

支持：
- 关键词、作者、标签、集合过滤
- 短语搜索 `"mixture of experts"`
- 前缀 `trans*`
- 中文分词：用 `simple` tokenizer + 二元组兜底（不引入 jieba 依赖，先够用）

### 8.5 导入 / 导出

| 方向 | 格式 |
|---|---|
| 导入 | arXiv ID / 链接（支持一次粘贴多条）、BibTeX、RIS、本地 `.zip`（LaTeX 源码）、`.tex`、PDF |
| 导出 | 中文 PDF、原文 PDF、译后 LaTeX 源码包、BibTeX、Markdown（笔记+译文） |

Zotero：v1 走 BibTeX 双向；v2 直接接 texlate 已有的 Zotero 7 插件（它能把生成的中文 PDF 回挂到条目）。

## 11. 阅读器

### 11.1 渲染管线

```
dual.json / segments(zh)
   → 原文：plain_src 中的 $...$ → KaTeX 渲染
   → 译文：zh（含占位符已回填）→ marked → 消毒(DOMPurify)
   → 段落按 ord 对齐，双栏同一 grid 行
```

**关键决策：阅读器渲染 HTML，不等 PDF。** PDF 只用于导出、打印、给别人的场景。这样首屏 300ms 内可读，且主题、字号、暗色模式全部可控。

### 11.2 同步滚动

不用像素百分比同步（两栏长度不同会漂移），用**段落锚点**：

- `IntersectionObserver` 选出视口内占比最大的段落 id。
- 另一栏 `scrollIntoView({block:'center'})` 到同 id 段落，加 400ms 平滑动画。
- 用户手动滚动某栏后 1.5s 内暂停同步，避免打架。
- 顶部显示两栏进度差，偏差 > 3 段时出现「对齐」按钮。

### 11.3 段落交互

| 操作 | 入口 | 行为 |
|---|---|---|
| 重译 | 段落 hover 按钮 / 右键 | 单段入队，替换译文 |
| 编辑译文 | 双击译文 | 行内编辑，保存为 `zh_edited=1` |
| 复制原文/译文/LaTeX | 右键菜单 | 写剪贴板 |
| 加术语 | 选中英文词 | 弹窗填译法，全局生效 |
| 笔记 | 右侧面板 | 绑定段落，导出时归组 |
| 查看引用 | 点 `[12]` | 悬浮卡片 + 一键译入 |

### 11.4 未译状态

| 状态 | 视觉 |
|---|---|
| pending | 灰色骨架条（宽 92%，微光） |
| running | 骨架 + 底部 2px 进度线 |
| failed | 淡红底 + 感叹号 + 「重译」 |

## 18. 引擎自持：fork texlate 怎么落地

### 18.1 为什么改成 fork

上游是 0.1.1、单人维护、迭代快（`pyproject.toml` 里成片的「另一会话在飞区」）。适配层能挡住 API 变化，挡不住两件事：

1. **能力缺口**：桌面版需要的「优先级队列」「按段重译」「人工修订回写 PDF」，上游没有。
2. **体验缺口**：编译失败时我们想拿到结构化错误直接展示，而不是解析日志字符串。

fork 之后这两类事都是一次小改动，而不是绕路。

### 18.2 目录与同步

```bash
# 首次引入
git subtree add --prefix vendor/texlate https://github.com/WncFht/texlate main --squash

# 每两周同步
git subtree pull --prefix vendor/texlate https://github.com/WncFht/texlate main --squash
```

```
vendor/texlate/
├── UPSTREAM.md        # 上游 commit、同步日期、已知冲突
├── PATCHES.md         # 改过的每个文件：原因、位置、上游是否已修
└── src/texlate/…      # 允许直接改
```

硬规矩：

- 每个 patch 在 `PATCHES.md` 登记 **文件 / 函数 / 为什么 / 上游是否已修**，同步时逐条核对。
- 改动尽量收敛成「新增文件 + 少量 hook」，别在核心流程里撒点。
- 回归集：30 篇 arXiv（cs.CL / cs.LG / cs.CV 各 10），每次同步全跑，编译成功率低于 90% 不许合入。

### 18.3 要改的六个点

| 能力 | 上游现状 | 改法 | 风险 |
|---|---|---|---|
| 优先级队列 | 顺序翻 | `chunk` 调度器加 `priority`，用户滚到的段插队 | 低 |
| 按段重译 | 只能整篇重试 | 新增 `retranslate(seg_ids)`，复用校验与缓存 | 低 |
| 人工修订进 PDF | 无 | 编译前把 `segments.zh_edited` 写回 tex | 中（转义处理） |
| prompt / 术语注入 | 内置固定 | 开放 `prompt_profile` 与 `glossary` 参数 | 低 |
| 并发与限流 | 固定 | 暴露 `concurrency` / `rps` 配置 | 低 |
| 结构化错误 | 日志字符串 | 编译结果补 `error_code` + `hint` | 中 |

### 18.4 许可证

Apache-2.0：保留 `LICENSE`、`NOTICE`，修改过的文件加「modified by Yijian」说明；安装包「关于」页放许可证全文。

## 19. 发现：本期只做全站热榜

范围收窄：P0 只有一个榜——**全站热榜**，直接用 alphaXiv 的 Hot 排序，客户端只做去重与打散。领域热榜、今日新稿、高引经典、为你推荐全部推迟到 P1，做法见 §19.7。

### 19.1 一个请求

```
GET https://api.alphaxiv.org/papers/v3/feed
    ?pageNum=0&pageSize=100&sort=Hot&interval=7%20Days
```

返回 `papers[]`，每条有 `universal_paper_id`、`version_id`、`title`、`abstract`、`topics`、`metrics{total_votes, visits_count}`、`github_stars`、`paper_summary`。

### 19.2 客户端做四件事

1. **去重**：按 `universal_paper_id`，再用标题归一化合并 HF / arXiv 的同名条目（实测同一篇会以两种 ID 各出现一次）。
2. **过滤**：已入库、已忽略。
3. **打散**：同一 `cs.XX` 最多 4 条，防一个方向包场。
4. **补中文**：`/papers/v3/{version_id}/overview/zh`，没有就显示英文摘要。

### 19.3 刷新：只把时间显示清楚

- 进页面：先出缓存，再后台请求一次。
- 点「刷新」：立即发请求，点几次发几次，不设冷却。
- 失败：不弹窗、不重试、不熔断，保留上一次数据，把时间标黄。
- 页面右上角**常驻**「数据更新于 12:40」；超过 24 小时标黄，超过 3 天标红。这就是全部的健康检查。

### 19.4 缓存

- 内存 + SQLite 双份，TTL 30 分钟（只是「什么时候顺手刷一次」的参考，不是限制）。
- 只留最近 300 条，按 `fetched_at` 淘汰。

### 19.5 表格

CREATE TABLE discovery_items (

  ax_id TEXT, version_id TEXT,

  topics TEXT,                -- JSON

### 19.6 卡片

标题、作者、分类药丸、热度（显示票数或位次，二选一，别造一个假分数）、3 行摘要、AI 速览（可折叠）、`译入文库` / `收藏` / `忽略`。

### 19.7 P1 再做的四个榜

### 19.8 出问题怎么发现

- 时间变黄或变红，就是接口坏了。
- 这时候再去设置页看「上次成功时间 + 错误原因」。
- 怎么修（改字段、换端点、还是换源），到时候看具体情况，现在不预设。

> alphaXiv 没有公开 OpenAPI，端点是社区从线上流量整理的。按「非官方接口」对待：超时 5 s、UA 带应用名与联系方式、不批量抓全文。真变了再说。

## 20. 这是应用，不是页面

### 20.1 先说明白

上一条交付的 `界面原型.html` 是**视觉稿**，用浏览器打开是为了让你两分钟看完三屏，不是产品形态。

产品是一个安装包：`译见-Setup-1.0.0.exe`。双击安装，开始菜单出现图标，双击打开独立窗口；没有地址栏、没有标签页、不需要启动任何服务；断网照样能读已译好的论文。

> 决策记录 · 2026-11-04：UI 渲染层采用 **WebView2**，§5 技术选型不变；「应用感」由 §20.3 的 12 项系统集成能力保证，不靠换 UI 框架。

### 20.2 判定标准

| 页面 | 应用 |
|---|---|
| 有地址栏，靠 URL 访问 | 独立窗口，靠 exe 启动 |
| 数据在服务器 | 数据在本地 SQLite + 文件目录 |
| 刷新就没了 | 关掉再开，进度、笔记、队列都在 |
| 只能看 | 托盘常驻、全局热键、文件关联、系统通知 |
| 升级靠刷新 | 自动更新、崩溃恢复、单实例 |

渲染层用什么技术，和「是不是应用」无关。VS Code、Slack、Obsidian、Zotero、Notion 都是 WebView/Electron，没人说它们是网页。**判定标准是生命周期和系统集成，不是渲染引擎。**

### 20.3 必做的 12 件事

| # | 能力 | 实现 | 优先级 |
|---|---|---|---|
| 1 | 安装/卸载、开始菜单、桌面快捷方式 | Inno Setup | P0 |
| 2 | 单实例，二次启动唤起已有窗口 | 命名互斥量 | P0 |
| 3 | 文件关联 + 拖拽（.pdf/.zip/.tex） | 注册表 + 拖放区 | P0 |
| 4 | 托盘：最小化、后台翻译、进度气泡 | pystray | P0 |
| 5 | 全局热键：翻译剪贴板里的 arXiv 链接 | `RegisterHotKey` | P1 |
| 6 | 原生打开/保存/选目录对话框 | pywebview / Win32 | P0 |
| 7 | 系统通知：译完、订阅更新 | Windows Toast | P1 |
| 8 | 任务栏进度条 | `ITaskbarList3` | P1 |
| 9 | 跳转列表（最近论文） | JumpList | P2 |
| 10 | 自动更新 | 自建 `latest.json` + 差分包 | P0 |
| 11 | 崩溃恢复、任务续跑 | jobs 表 + 启动扫描 | P0 |
| 12 | 离线可用 | 全本地存储 | P0 |

### 20.4 如果要「连 UI 都不用 WebView」

那只有 PySide6 一条路，代价说清楚：

| 影响 | 说明 |
|---|---|
| 公式排版 | Qt 没有 KaTeX，只能把 LaTeX 预渲染成 SVG/图片贴进去；选中、缩放、复制公式都会退化 |
| 阅读体验 | 双语分栏、同步滚动、主题切换都要手写，CSS 那套能力放弃 |
| PDF 预览 | `QPdfView` 是原生的，这块反而更好 |
| 工期 | +3～4 周，且第一版大概率不如 WebView 版好看 |

建议：**壳用原生能力，内容区用 WebView2**——托盘、热键、关联、通知、更新都是 Python 原生实现，WebView 只画阅读区。Zotero、Calibre、Obsidian 都是这个结构。

如果明确要求「零 WebView」，我把 §5 技术选型改成 PySide6 并重排工期，其余章节不受影响。
